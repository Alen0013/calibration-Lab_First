# ЛР1 Вариант 25 Калибровка вероятностей

Воспроизводимый разведочный анализ Breast Cancer Wisconsin Diagnostic и демонстрация калибровки вероятностей. Проект включает локальное приложение, CLI, отчёт, исходные данные с SHA-256, MLflow, pre-commit, негативные контроли и конфигурацию GitHub Actions.

## Быстрый запуск Windows

Установите **Python 3.12** и **Git**. Распакуйте проект в обычную папку. Дважды нажмите `start_windows.bat`. При первом запуске создаётся `.venv` и устанавливаются зависимости; затем открывается `http://127.0.0.1:8765`. Для установки нужен интернет. Сохранённые результаты и данные уже входят в проект.

В PowerShell из папки проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev]"
.\.venv\Scripts\python -m calibration_lab.webapp
```

Если политика PowerShell запрещает активацию окружения, используйте команды выше: активация не требуется.

## Linux и macOS

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m calibration_lab.webapp
```

Приложение запускается с корнем текущего проекта, слушает только `127.0.0.1` и не требует облачного сервиса. Остановить его можно `Ctrl+C` в терминале.

## Команды лабораторной

В активированном окружении, из корня проекта:

```bash
python -m calibration_lab.cli prepare --config configs/lab1.yaml
python -m calibration_lab.cli verify --config configs/lab1.yaml
python -m calibration_lab.cli eda --config configs/lab1.yaml
python -m calibration_lab.cli reproduce --config configs/lab1.yaml
python scripts/negative_controls.py
python -m pytest
python -m pre_commit install
python -m pre_commit run --all-files
```

`prepare` получает официальную копию из установленного scikit-learn и сверяет фиксированный ожидаемый SHA-256. Для загрузки по HTTPS используйте `prepare --download` при отсутствии файла данных. В поставляемом проекте CSV уже скачан по HTTPS и проверен. Анализ не меняет эталонный хеш. `verify` проверяет данные по манифесту. `eda` сохраняет таблицы, графики и настоящий MLflow run. `reproduce` сравнивает результаты двух прогонов. Отрицательные контроли пытаются выполнить три настоящих коммита во временном репозитории.

## Что означает калибровка

При корректной калибровке среди объектов, которым модель присвоила вероятность события около 0.8, событие в среднем встречается примерно в 80% случаев. Высокая accuracy сама по себе этого не гарантирует. В проекте событие — злокачественный класс: исходная метка `0` преобразуется в положительную метку `1`.

LogisticRegression обучается на train, сигмоидальная калибровка — на отдельной calibration-части. Итоговые вероятности сравниваются на общей отложенной test-части. Стандартизация обучается только на train. Разбиение стратифицированное, seed фиксирован. На малой выборке калибровка может ухудшить отдельные метрики; отчёт сохраняет полученный результат без подбора удобного seed.

## Восстановление истории Git из архива

В комплекте есть `calibration_lab1.bundle` со всеми локальными ветками. Чтобы получить обычный репозиторий с историей:

```bash
python scripts/restore_git.py
```

Рядом с распакованной папкой появится `calibration-lab1-git` с полной историей и всеми локальными ветками. Уже существующий каталог скрипт не перезаписывает. После подключения настоящего GitHub добавляется его remote и отправляются подготовленные ветки. Подробнее — `docs/git_workflow.md`.

## Воспроизводимость и ограничения

Основная поддерживаемая среда — Python 3.12. Прямые зависимости зафиксированы в `pyproject.toml`. **В проекте сохранены два разных снимка окружения**: их нельзя использовать как взаимозаменяемое описание одного запуска.

| Снимок | Что описывает | Что проверено |
| --- | --- | --- |
| `requirements-run.txt` и `reports/LAB1/run_environment.json` | Фактическая среда основного EDA и повторов | Числа отчёта и совпадение результатов двух повторных прогонов относятся к этой среде |
| `requirements-lock.txt` и `reports/LAB1/local_checks.json` | Независимая установка в чистое окружение без системных пакетов | Установка, зависимости, автоматические тесты, pre-commit и проверка данных; HTTP-проверки приложения описаны отдельно в `app_smoke.json` |

Снимки различаются, в частности, версиями SciPy, joblib и threadpoolctl. Расширенный снимок основной среды выполнен после анализа из того же окружения; время и способ фиксации указаны в `run_environment.json`. Сведения независимой установки находятся в `local_checks.json`. Побайтовое совпадение детерминированных файлов подтверждено между повторами **в одной среде основного прогона**. Сохранённые проверки чистой установки не доказывают численное или побайтовое совпадение результатов между этими двумя средами. Для такого утверждения нужен отдельный сопоставимый эксперимент; он здесь не заявляется.

`mlruns/` хранится локально и исключён из Git. В корне архива сдачи находятся `mlflow_runs_snapshot.zip` и `MLflow_SNAPSHOT_README.txt`. Это снимок реальных прогонов для аудита; он может содержать абсолютные пути исходной среды. Его не следует подключать как готовый переносимый tracking store. Новые запуски проекта создают собственный свежий `mlruns/`; подробности приведены в файле пояснения. Эти два файла не включаются в Git-репозиторий.

Проверка GitHub Actions, серверная защита `main` и URL репозитория подтверждаются только после публикации в аккаунте владельца. Наличие YAML и локальных успешных тестов не означает, что серверный CI уже выполнен. Порядок завершения описан в `docs/git_workflow.md`.

Проект относится к учебному анализу открытого датасета. Он не предназначен для диагностики новых пациентов. Источник и лицензия данных перечислены в `docs/sources.md`.
