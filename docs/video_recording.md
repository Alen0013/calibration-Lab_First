# Автоматическая запись работающего приложения

Скрипт `scripts/record_demo.py` записывает настоящий интерфейс локального приложения с текстовыми пояснениями. Он открывает разделы, нажимает кнопки запуска, ждёт ответа сервера и проверяет код завершения каждой команды. Результат — `artifacts/lab1_demo.webm`. Целевая длительность составляет примерно 3 минуты 30 секунд, разрешение — 1600 × 1000. Микрофон и системный звук не записываются.

Этот скрипт подготовлен для запуска на компьютере владельца. В среде подготовки проекта Chromium не удалось запустить из-за ограничений среды, поэтому успешная запись графического интерфейса здесь не заявляется. Синтаксис скрипта и работа командной строки проверены; сам сценарий с браузером нужно выполнить на компьютере владельца.

## Подготовка на Windows

Установите Python поддерживаемой проектом версии и Git, затем откройте PowerShell в корне проекта. Если окружение уже создано, используйте его. Для нового окружения:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,video]"
.\.venv\Scripts\python.exe -m playwright install chromium
```

Официальная команда Playwright устанавливает совместимую версию Chromium. После обновления Playwright установку браузера может потребоваться повторить. См. [документацию браузеров Playwright](https://playwright.dev/python/docs/browsers).

Перед съёмкой выполните подготовку данных и первый прогон блокировок. Это проверит окружение и заполнит кэш pre-commit вне записи:

```powershell
.\.venv\Scripts\python.exe -m calibration_lab.cli prepare
.\.venv\Scripts\python.exe scripts\negative_controls.py
```

`prepare` использует проверенную копию датасета, уже включённую в проект, либо установленный scikit-learn. Чтобы первоначально получить отсутствующий файл с официального адреса по HTTPS, используется `prepare --download`. Существующий испорченный файл намеренно не перезаписывается: исправьте причину ошибки до записи.

## Запуск записи

```powershell
.\.venv\Scripts\python.exe scripts\record_demo.py
```

Скрипт сам запускает локальный сервер, если приложение ещё не открыто. Если сервер уже работает на `http://127.0.0.1:8765`, он используется повторно. Сервер, запущенный пользователем, скрипт не останавливает; собственный сервер завершает после записи. В уже открытом приложении не должна выполняться другая команда.

Откроется окно Chromium. Не нажимайте кнопки в нём во время автоматической демонстрации: скрипт выполняет сценарий сам. В конце найдите:

- `artifacts/lab1_demo.webm` — запись успешного сценария.
- `artifacts/lab1_demo_recording.json` — статусы действий, фактические журналы, отметки времени, SHA-256 видео и идентификатор MLflow-прогона.
- `artifacts/lab1_demo_server.log` — журнал сервера, если его запустил скрипт.

Значения в титрах считываются из текущего результата приложения. Скрипт не заменяет ошибку успешной надписью. При отказе команды сценарий прерывается; если браузер смог сохранить запись, она получает имя `lab1_demo.failed_ДАТА_ВРЕМЯ.webm`. Такая запись не является готовым видео для сдачи.

## Что показывается

| Этап | Демонстрация |
| --- | --- |
| Запуск анализа | Реальная команда EDA, новый MLflow run, обновлённые результаты |
| Анализ данных | Объём, признаки, пропуски, классы, корреляции и IQR-флаги |
| Калибровка | Диаграмма и фактическое изменение Brier на фиксированном test |
| Целостность | Совпадение SHA-256 с закреплённым эталоном |
| Подмена | Отказ при изменении байта временной копии |
| Git | Три реальные блокировки коммитов с понятными причинами |
| Воспроизводимость | Два прогона и сравнение артефактов |
| Тесты | Настоящий запуск pytest и его результат |
| Материалы | Отчёт, таблицы, журналы и происхождение результата |

Проверки в ролике запускаются заново и обновляют свои файлы результатов. Если после записи нужен отчёт с идентификатором именно показанного EDA-прогона, пересоберите отчёт по текущему `results.json` принятой в проекте командой. Не оставляйте в сдаваемом отчёте ссылку на случайный другой запуск без пояснения.

## Дополнительные параметры

```powershell
.\.venv\Scripts\python.exe scripts\record_demo.py --seconds 240
.\.venv\Scripts\python.exe scripts\record_demo.py --url http://127.0.0.1:8766
.\.venv\Scripts\python.exe scripts\record_demo.py --output artifacts\my_lab1.webm
.\.venv\Scripts\python.exe scripts\record_demo.py --headless
```

`--seconds` задаёт целевую длительность от 180 до 290 секунд. Скрипт не ускоряет реальные действия; на медленном компьютере проверки могут занять больше отведённых пауз. Если закончить полный сценарий за пять минут не получилось, запись помечается неуспешной. Прогрейте окружение, закройте лишние приложения и повторите. `--step-timeout` задаёт ожидание одного действия, по умолчанию 120 секунд.

Не меняйте расширение `.webm` на `.mp4` простым переименованием. Если нужен MP4 и установлен FFmpeg, выполните преобразование:

```powershell
ffmpeg -i artifacts\lab1_demo.webm -c:v libx264 -crf 20 -pix_fmt yuv420p -movflags +faststart artifacts\lab1_demo.mp4
```

Запись финализируется при закрытии контекста браузера; совпадение размеров viewport и video сохраняет читаемость интерфейса. Это предусмотрено официальным механизмом [Playwright Video](https://playwright.dev/python/docs/videos).

## Проверка перед сдачей

Откройте видео и убедитесь, что текст читается, графики загружены, действия завершились, нет сообщений об ошибках, а длительность составляет 3–5 минут. Если установлен `ffprobe`, скрипт измеряет длительность видео; иначе в JSON сохранена только оценка по реальному времени, а точную длительность нужно проверить в проигрывателе.

Демонстрация локальных проверок не подтверждает выполнение GitHub Actions или настройку защиты `main`. После публикации репозитория добавьте собственный короткий фрагмент с фактическим статусом GitHub либо назовите оставшуюся настройку в объяснении. Для самостоятельной озвучки используйте `docs/video_script.md`.
