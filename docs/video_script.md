# Сценарий скринкаста

Целевая длительность — примерно 3 минуты 30 секунд. Методичка разрешает 3–5 минут, ускорение и текстовые подписи. Записывается работа запущенного приложения с реальными результатами; таблицы и журналы должны читаться при просмотре видео.

## Подготовка

Выполните установку по `README.md`. Откройте приложение и терминал в корне проекта, увеличьте шрифт терминала. Подготовьте вкладки с отчётом и GitHub. Отключите всплывающие уведомления. Запишите своё имя, вариант и номер работы в начале ролика. Если демонстрация производится до подключения GitHub, сохраните этот статус в титре и затем добавьте отдельный фрагмент с удалёнными проверками.

## Команды для демонстрации

После активации окружения используйте команды из `README.md`. Основные команды анализа:

```bash
python -m calibration_lab.cli verify --config configs/lab1.yaml
python -m calibration_lab.cli tamper --config configs/lab1.yaml
python scripts/negative_controls.py
python -m calibration_lab.cli reproduce --config configs/lab1.yaml
git log --graph --decorate --oneline --all
```

Журнал негативных контролей сохраняется в `reports/LAB1/precommit_block.log`, машиночитаемый итог — в `precommit_controls.json`. Подробности содержит `docs/git_workflow.md`. Команда `tamper` сохраняет `reports/LAB1/hash_tamper.log` и `hash_tamper.json`. Она проверяет намеренно повреждённую временную копию; не редактируйте основной файл ради записи. Для повторяемости показываются `reports/LAB1/reproducibility.json` и `reproducibility.log`.

## Как записать на Windows

Откройте программу записи экрана, выберите захват окна или экрана с приложением и терминалом, включите микрофон при необходимости. Подходит любая программа, которая умеет сохранять MP4. Сделайте короткую пробу: проверьте читаемость шрифта, звук и попадание всех окон в кадр. Затем запишите сценарий одним проходом либо соедините фрагменты без скрытия сообщений об ошибках.

Можно использовать голос или текстовые подписи. Подписи должны объяснять действие и его результат; одного перелистывания статических картинок недостаточно для демонстрации работающего приложения. Если ожидание ускорено, обозначьте это в титре. Не вставляйте придуманный успешный статус вместо реального результата команды.

## Проверка готового ролика

- Видны работа приложения и реакция на действия оператора.
- Понятен смысл графика калибровки, показаны измеренные метрики.
- Присутствуют три блокировки коммита и обнаружение подмены данных.
- Показан результат повторного запуска, а не только команда.
- Номер варианта, значения и версия кода согласованы с отчётом.
- Длительность укладывается в требования методички.
- Состояние GitHub названо честно; подготовленный workflow не выдаётся за успешный серверный запуск.
